# 自然声探员剩余体验优化清单

审计日期：2026-07-31  
范围：优化后的首屏、录音确认、结果、连续采集和错误恢复。  
目标：从“可以完成一次识别”推进到“适合户外亲子连续使用、比赛现场稳定演示、能够积累有效反馈”。

## 总体判断

当前主流程已经清楚，下一阶段不应继续堆视觉装饰。剩余价值最高的工作集中在四件事：真实手机上的结果顺序、比赛演示兜底、儿童录音隐私、识别反馈闭环。

## 1. 首屏与连续采集 — 良好，但还不是“成长记录”

![返回首屏](../outputs/remaining-experience-audit/02-return-home.png)

“查看上一次”解决了误触丢失，但只能恢复一条结果，无法表达项目最初提出的声音集邮和自然成长记录。

建议：

- 首页增加“我的声音册 · 3”入口，最近结果按日期、地点和声音类别排列。
- 每张记录支持重新播放、查看依据、保存卡片和删除。
- 比赛 MVP 先保存在当前设备，不必立即建设账号系统。
- 增加“试用示例”，让评委在嘈杂会场、没有麦克风权限或网络较慢时也能在 10 秒内看到完整结果。

## 2. 录音确认 — 可用，缺少质量判断

![录音确认](../outputs/remaining-experience-audit/03-ready.png)

时长契约已经清楚，但页面仍只告诉用户“有一段文件”，没有判断它是否适合识别。

建议：

- 前端本地计算音量、静音比例和削波比例，提交前提示“声音较小”“人声较多”或“适合识别”。
- 将技术文件名降为次级信息，主标题显示“已有录音 · 19 秒”或“刚刚录制”。
- 对超过 20 秒的录音提供简单的片段选择，而不是永远取开头。
- 真实录音结束前 3 秒加入视觉倒计时；自动结束后给予轻微震动反馈（设备支持时）。

## 3. 结果理解 — 桌面良好，手机顺序需要调整

![当前结果](../outputs/remaining-experience-audit/01-current-result.png)

桌面双栏结构清楚。但在 `760px` 以下代码会变为单栏，DOM 顺序仍是“声音卡片 → 保存/播放 → 儿童解释”。手机用户需要先滚过大卡片才能看到真正的识别结论。

建议：

- 手机端改为“置信度与主要声音 → 儿童解释/观察问题 → 播放 → 声音卡片与保存”。
- 声音卡片默认使用紧凑预览，点击后再展开完整海报。
- “保存卡片”完成后显示明确反馈，例如“已保存到下载”，并防止重复点击生成多份文件。
- 首页与结果页都增加能力边界说明：当前可判断自然声音大类，鸟类可进一步给出杭州候选种；蛙类和昆虫暂不保证到物种级。

## 4. 识别纠错 — 当前缺失，建议作为核心功能

对比赛和后续模型迭代而言，结果页应该允许家长表达“像 / 不太像”。这既改善信任，也能形成杭州本地数据闭环。

建议：

- 家长依据下增加“这个结果像吗？”以及“像 / 不太像”。
- 选择“不太像”后展示已有类别供更正，并允许填写“听不出来”。
- 保存录音、模型版本、原结果、更正结果和时间，但必须先说明用途和保留周期。
- 儿童主视图不展示准确率或纠错表单，避免打断探索感。

## 5. 错误恢复 — 功能存在，文案和焦点表现需要细化

![格式错误](../outputs/remaining-experience-audit/04-error.png)

优点：错误标题会获得焦点，屏幕阅读器可以及时获知失败。

问题：

- 程序聚焦标题后出现面积很大的浏览器默认黄色轮廓，视觉上像表单校验错误。
- “重新尝试”没有根据原因变化。格式错误时应该“重新选择录音”，网络错误时才适合“再次提交”。
- 错误页没有说明已选择的录音是否仍被保留。

建议：为程序性标题焦点提供不干扰视觉的样式；按错误类型设置标题、解释和下一步按钮；明确“录音已保留”或“需要重新选择”。

## 6. 隐私与数据保留 — 上线前必须补齐

当前服务端会把上传录音和任务 JSON 保存到 `outputs/mvp/`，没有自动清理机制。亲子户外录音可能包含儿童人声、同行者对话和精确地点，不能只依赖页面底部的识别免责声明。

建议：

- 默认只保存完成识别所需的最短时间，例如 24 小时后自动删除原始录音。
- 首次录音前用一句话说明“录音用于本次识别，可能包含环境人声”。
- 参与模型改进必须单独选择加入，不能和识别服务绑定。
- 地点默认只保留公园/区域级，不采集精确坐标；若调用定位，先说明用途。
- 提供“删除本机记录与服务器录音”的入口。

## 7. 户外网络与演示稳定性 — 尚未覆盖

当前依赖远程大模型，弱网、断网或接口限流时体验会中断。

建议：

- 上传前显示网络状态；断网时保留录音并提示稍后提交。
- 对相同录音避免重复创建远程任务。
- 准备 2–3 条缓存示例结果，比赛现场即使 API 不稳定也能演示完整闭环。
- 把 BirdNET 本地结果先展示为“初步鸟声线索”，远程结果完成后再补充内容，降低等待感。

## 优先级建议

### P0：比赛展示和真实试用前

1. 增加“试用示例”和缓存结果，保证现场可演示。
2. 调整手机端结果顺序，让识别结论先于分享卡片出现。
3. 建立录音删除与保留周期，补充儿童录音隐私说明。
4. 修复错误页焦点轮廓，并按错误类型提供正确的恢复动作。

### P1：形成产品差异

1. 提交前音质检查。
2. “像 / 不太像”反馈与人工纠错。
3. 从“查看上一次”升级为本机声音册。
4. 家长依据增加时间片回听和模型一致/冲突说明。

### P2：后续扩展

1. 地点推荐与公园级定位。
2. 弱网队列和稍后提交。
3. 儿童声音挑战、答题和集邮进度。
4. 多条记录生成自然观察周报或成长视频。

## 暂时不建议做

- 暂不优先加入复杂音乐、视频生成；当前识别可信度、反馈闭环和连续采集更影响项目完整性。
- 不增加更多装饰动画和图标；户外强光与手机性能下，清楚、快速比视觉复杂度更重要。
- 不急于做账号登录；本机声音册足以验证核心需求。

## 证据限制

- 本轮在约 812px 宽的内置浏览器窗口验证；真正的 390px 手机结果顺序由当前 DOM/CSS 推断，仍需 iPhone Safari、安卓 Chrome 和微信内置浏览器实测。
- 未接受麦克风权限，录音倒计时、系统权限弹窗和真实户外噪声下的操作仍未验证。
- 未执行卡片下载，因此系统下载反馈和相册权限仍需单独测试。
