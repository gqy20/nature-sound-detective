# 候选动物故事接入

> 文档状态：Web MVP v0.1  
> 更新时间：2026-08-24  
> 当前边界：暂不建设物种知识库

## 1. 产品目标

声音分析得到动物候选后，儿童需要先选择实际观察到的时间、环境、活动、声音特点和可见外形，再生成一则以该动物本身为主角的故事。故事必须使用这些现场观察，不参与物种确认。

```text
声音候选
→ 选择候选动物与多维现场观察
→ 至少完成两个有效观察维度
→ 文本模型生成结构化故事
→ 安全策略校验
→ Web故事卡
→ 保存到当前调查
```

## 2. 当前故事类型

| 值 | 内容 |
|---|---|
| `animal_life` | 这个候选动物怎样生活，默认类型 |
| `why_it_calls` | 这个候选动物为什么发声 |

第一版Web只展示默认的`animal_life`，CLI可以选择两种类型。

## 3. 候选来源

故事候选必须来自当前融合结果：

1. 优先使用`result.detections[].specific_species`中的具体动物；
2. 最多显示三个候选；
3. 没有具体物种但大类为鸟、蛙、昆虫时，退回类群故事；
4. 风、雨、流水、人声或交通等非动物结果不显示动物故事入口；
5. 浏览器提交的候选ID必须由服务端再次校验。

## 3.1 统一现场观察Schema

Python、Web与Flutter共享`mobile/assets/config/field_observations.json`，包含：

-时间：清晨、白天、傍晚、夜间；
-环境：高处树冠、灌木、草丛、地面、水边、水面、建筑附近；
-活动：独自、成群、移动、停留、疑似寻找食物、躲藏；
-声音：重复、连续、短促、间隔、单方向、多方向；
-外形：头部、身体颜色、体型、翅膀或腿部特征。

至少两个非“无法判断”维度才能完成观察。旧Flutter `time/location/appearance`核对数据保留兼容，但新故事只使用结构化观察。

## 4. 无知识库模式

当前模型只接收：

-候选中文名与学名；
-候选层级；
-声音大类；
-杭州区域信息；
-故事类型；
-用户实际选择的结构化现场观察；
-事实与安全约束。

不发送原始音频、儿童自由文本或精确位置。

模型必须自然使用每一项有效观察；未使用任何一项时故事会被拒绝并回退模板。观察只描述“故事里这只候选动物当时的活动”，不能扩写成该物种永远如此。

由于没有外部知识库，Prompt禁止：

-精确寿命、数量、距离和繁殖数字；
-保护等级和稀有程度；
-未经核验的独特习性；
-把当前录音写成已确认物种；
-追逐、捕捉、触摸、投喂、爬树、下水或靠近巢穴。

生成后再次执行长度、危险行为、虚假确认、精确数字和候选名称校验。不通过时自动使用安全模板。

## 5. 模型配置

默认不产生费用：

```dotenv
STORY_MODE=template
```

启用OpenAI兼容文本接口：

```dotenv
STORY_MODE=live
STORY_MODEL=qwen3.7-flash
STORY_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
STORY_API_KEY=
```

`STORY_API_KEY`未配置时会回退到`DASHSCOPE_API_KEY`。模型只生成文本故事，与已移除的Qwen Omni音频分析无关。

## 7. API

本地有状态任务：

```http
GET /api/jobs/{job_id}/story-candidates
POST /api/jobs/{job_id}/stories

{
  "candidate_id": "Pycnonotus sinensis",
  "story_type": "animal_life"
}
```

故事按`candidate_id|story_type|observation_fingerprint|model`缓存在任务JSON中。观察内容变化后不会返回旧故事。

Vercel轻量版：

```http
POST /api/stories

{
  "result": {},
  "candidate_id": "category:bird",
  "story_type": "animal_life",
  "location": "杭州",
  "investigation": {}
}
```

云端无任务数据库，因此返回后由Web声音册保存在当前设备。

## 8. Web交互

结果为动物声音时先显示多维现场观察；完成后才显示“听它的故事”：

```text
什么时候发现的？ [清晨] [白天] [傍晚] [夜间]
它在哪里活动？ [高处树冠] [低处灌木] [草丛] [水边]
它正在做什么？ [独自] [成群] [移动] [停留]
声音有什么特点？ [重复] [连续] [短促]

[完成现场观察]

认识候选动物
[听白头鹎的故事] [听乌鸫的故事]

故事标题
故事正文

下次可以观察
……

AI创作 · 候选不是确认
```

状态包括：

-等待选择候选；
-正在准备故事；
-故事完成；
-读取缓存；
-模型或网络失败；
-安全校验失败后使用模板。

演示示例不调用故事API，避免伪造持久任务。

```powershell
uv run python -m app.cli story "artifacts/cli-runs/<run-id>"
uv run python -m app.cli story "artifacts/cli-runs/<run-id>" `
```

## 10. 当前验收范围

-候选只能来自当前分析结果；
-故事生成前必须完成至少两个有效观察维度；
-故事必须使用全部有效现场观察；
-非动物结果不显示故事；
-模型输出必须通过安全校验；
-模型失败时故事功能仍可用；
-同一候选故事不重复调用；
-CLI、任务API和云端API使用同一故事服务；
-Web显示候选声明和AI内容标签；
-原始音频不发送给故事模型；
-暂不宣称故事中的物种事实已经过知识库逐条核验。

## 11. 下一阶段

知识库建设后，输入应增加`verified_facts`和事实ID，输出增加`facts_used`，并拒绝任何无法映射到审核事实的物种陈述。在此之前，故事属于低风险、宽泛的候选动物科普创作，不作为调查证据。
