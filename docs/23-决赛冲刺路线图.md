## 1. 现状盘点（2026-08-22）

### 1.1 已完成

- **v0.1.0 发布**：Web 展示端 + Flutter Android 端 + Python/FastAPI 服务端，含结构化日志、跨端 trace ID 与诊断导出。
- **识别链路**：YAMNet 通用声景 + BirdNET 2.4 杭州 200 种鸟类候选 + 12 类非鸟分类头 + 官方参考声匹配层；正式分析全部使用本地声学模型，不调用通用音频大模型。
- **创作闭环**：MiniMax 音乐/旁白 + 通义万相 Wan 2.7 画面 + FFmpeg 三轨合成，`mock/reuse/live` 三种视频模式。
- **共听杭州 MVP**：Neon 数据库 + Vercel Blob 存储，区域级声景图、匿名探索卡、结构化协助、分层授权与撤回。
- **公开物料**：ModelScope 创空间上线且 Design QA 通过，B 站发布方案与宣传视频流程在收尾，参赛 PDF 导出脚本已建。

### 1.2 已具备但未形成闭环（决赛最大缺口）

| 缺口 | 现状 | 影响 |
|---|---|---|
| 观察任务不是主流程必经步骤 | `fieldChecks` 数据结构与 `SpeciesDetailPage` 编辑已存在，但识别结果页之后没有"继续调查"的必经引导 | 法官打开 App 看到的是"分类器 + 可选的反馈"，不是"调查 Agent" |
| 声音册是记录列表，不是声音邮票 | `NatureBookPage` 展示同质化卡片（标题/时间/时长），无调查状态流转 | 产品总纲核心对象"声音邮票"未落地 |

| 无真值测试集 | 360 条野外候选听审全部 `pending` | 识别能力无法正式验收 |

## 2. 决赛核心命题：Agent 原生

### 2.1 现状诊断

项目曾使用Qwen3.5-Omni同时承担通用声景分析、解释和观察问题，但其结果与YAMNet/BirdNET/非鸟分类头大量重复，并增加远程延迟、费用、隐私传输和模型冲突。2026-08-24决定将其从正式链路中删除，不再作为运行时fallback。

当前核心问题不再是“如何让大模型参与更多”，而是：

- 如何让三类本地声学模型共享时间片、来源和候选状态；
- 如何用确定性问题策略把机器候选转化为现场行动；
- 如何把儿童观察写回调查状态，而不是停留在可选反馈；
- 如何让生成模型只在调查完成后消费受控创作简报；
- 如何在CLI、API、Web、Flutter和ModelScope之间维持同一契约。

结论：**Agent原生来自有目标、有状态、有人机协同和可恢复的调查流程，不来自强行加入通用大模型。**

### 2.2 Agent 原生的判据与本项目定义

Agent 原生 ≠ 去掉安全护栏，而是把"目标驱动、工具使用、循环与分支、规划与反思、记忆与状态、人机协同"引入调查流程。对本项目的具体定义：

> Agent 的目标不是"把音频分类"，而是**以最小的证据成本，帮助孩子完成一次可追溯、可修正的自然调查**。推理层 Agent 化，内容与安全层保持确定性与可审计性。

## 3. 五条工作线（按杠杆排序）

### Track A：调查 Agent 闭环（叙事天花板）

目标：把"录音 → 看结果"变成"录音 → AI 提猜想 → 现场验证（必经）→ 声音邮票 → 三层选择 → 贡献可见"。

- [ ] A1 观察任务入主流程：识别结果页后插入必经"继续调查"步骤，至少完成一项 `fieldCheck` 才能结案；
- [ ] A2 声音册升级为声音邮票：卡片展示调查状态（等待观察 / 调查已完成 / 公众协助中 / 等待复核），状态来自 `fieldChecks`、`confirmedByUser` 与社区 `review_status`；
- [ ] A3 贡献闭环 UI：社区页面展示审核状态并加入撤回按钮（后端端点已存在，纯 UI 层缺失）；
- [ ] A4 三层权限文案与状态正确性回归（私人 / 匿名探索卡 / 人工复核已在前端实现，需按总纲核对）。
- [x] A5 Web候选动物故事MVP：从真实候选生成关于动物本身的儿童故事，包含候选声明、安全校验、任务缓存、云端无状态接口和CLI入口；知识库事实引用留待后续补充。

### Track B：识别能力扎实（评委可能真测）

目标：十二分类头可经得起官方素材与真实手机录音测试。

- [ ] B1 完成 360 条野外候选听审（`challenge_2026_nonbird_review_candidates.csv`，全部 `pending`）；
- [ ] B2 从听审结果抽取杭州相关记录，按地点/日期隔离构建真值测试集；
- [ ] B3 修复弱项物种：纺织娘、黑斑侧褶蛙 F1=0，孟闻琴蛙召回低——用官方标准声 + iNaturalist 可追溯素材做数据增强；
- [ ] B4 手机频响/16kHz 重采样增强：训练时加入手机频响模拟，目标把两类条件 F1 从 0.57/0.58 提升到 0.7 以上；
- [ ] B5 为官方 21 物种中 3–5 个代表物种准备"清晰 → 正确识别"与"混合/低质 → 谨慎拒识"的对比演示案例。

### Track C：演示资产与彩排（比赛不出事故）

- [ ] C1 三条演示场景（清晰鸟鸣 / 风和树叶 / 混合公园声景）完成人工听审，确认关键片段位于前 20 秒；
- [ ] C2 三次完整端到端彩排，每次演练含故障预案切换（断网、模型超时、贡献接口失败）；
- [ ] C3 固定演示状态：地图展示预置数据、视频用 `reuse` 模式、贡献展示已有审核记录而非现场触发；
- [ ] C4 现场设备与网络预案：备用机、离线案例包、本地完整版可用性检查。

### Track D：数据责任可视化（差异化优势）

- [ ] D1 隐私承诺可视化：演示 24 小时清理时间戳、三层授权与撤回路径，而不是口头承诺；
- [ ] D2 敏感物种位置规则抽查（模糊 / 延迟 / 不公开）；
- [ ] D3 答辩口径：不把候选当准确率、不把参考匹配当泛化能力（见 [2026 挑战数据基线](./21-2026挑战数据基线.md)）。

### Track E：CLI、回放与真实交互一致性（工程底座）

目标：让一次声音调查可以从命令行分阶段运行、保存、检查、提交观察和离线回放；CLI与FastAPI共享同一份证据结构和调查状态迁移，不复制业务规则。

- [x] E1 建立共享调查Schema：统一证据、问题、观察、状态、轮次、决策历史和停止原因；
- [x] E2 API任务完成后自动生成调查状态，并提供统一现场观察提交端点；
- [x] E3 CLI第一阶段：`doctor`、`analyze`、`inspect`、`investigate/observe`、`replay`；
- [x] E4 运行包默认不复制原始录音，保存输入SHA-256、trace ID、融合结果、调查状态和阶段进度；
- [x] E5 增加CLI、JobStore和真实FastAPI端点的一致性契约测试；
- [ ] E6 Flutter在线调查接入共享Schema；离线模式保持相同状态语义；
- [ ] E7 增加模型/阈值/规则版本比较、候选更新差异和三条演示案例一键验收。

详细设计与当前实现边界见 [CLI 与真实交互一致性调试体系](./24-CLI与真实交互一致性调试体系.md)。

## 4. Agent 原生改造路线（与 Track A 并行）

### L1：本地多模型证据编排（当前实施）

YAMNet处理通用声景，BirdNET处理鸟类候选，非鸟分类头处理蛙虫候选；三者并行运行后由规则层统一时间片、主次线索、拒识和能力边界。问题策略只从审核过的安全问题中选择，不开放自由生成。

- 验收：同一录音在CLI、本地API、Android和ModelScope输出类别来源一致；任一模型失败时其他证据仍可展示；分析过程不发起通用大模型请求。

实施状态（2026-08-24）：服务端YAMNet已接入，正式管线、CLI和Vercel轻量API已移除Qwen调用；OpenAI SDK依赖和Qwen音频测试入口已删除。详见 [本地多模型编排与生成模型职责](./25-本地多模型编排与生成模型职责.md)。

### L2：有界多轮调查循环

孩子回答观察问题后，答案回传为**新证据**。决赛版默认一轮，由确定性规则记录支持、未观察到或无法判断；后续只有在真实用户测试证明必要时才增加第二轮。

- 验收：回答"声音来自高处树冠"等观察后，候选排序发生可解释变化；超轮次自动结案并给出状态。

### L3：可解释决策轨迹

在结果页可视化调查步骤（"我检查了音质 → 定位到第4–7秒 → 专业模型提出候选 → 你补充了现场观察 → 当前仍保留哪些不确定性"）。不建设多角色大模型系统；内容与安全层保持确定性模板和受控插槽。

- 验收：儿童与家长能读懂调查轨迹；任何输出都可追溯到一个可审计的决策步骤；儿童可见内容仍全部经过受控模板。

## 5. 排期与闸门（决赛日期待定，按相对周排）

| 周 | 目标 | 交付物/闸门 |
|---|---|---|
| W1 | Track A 主线 + L1 + Track E | A1 观察任务主流程可演示；共享调查Schema、CLI/API一致性和L1固定案例跑通 |
| W2 | Track B 数据与模型 | B1 听审推进过半；B3/B4 弱项修复后 F1 报告更新 |
| W3 | Track A 收尾 + Track C | A2/A3 声音邮票与贡献闭环；C1 三条案例人工确认 |
| W4 | Track C + D + 彩排 | 三次端到端彩排完成；D1 隐私演示脚本；全部 pytest 与 flutter analyze 通过 |
| 决赛前 | 冻结功能，只修 P0 | 提交包、离线演示包、答辩口径与故障预案演练 |

闸门规则：功能类改动最迟在决赛前 3 天冻结；模型改动必须附带更新后的评测报告；新增能力不得挤占彩排时间。

## 6. 分工

### 技术/产品负责人

- Track A 主流程改造（A1–A3）；L1/L2/L3 Agent 改造；
- Track B 数据增强、弱项修复与评测报告；端到端集成。

### 生态/数据负责人

- Track B 听审推进（B1/B2）与真值集构建；Track C 演示案例听音核验；
- 物种知识、儿童文案与三层权限文案审核；亲子彩排与反馈记录。

### 共同完成

- 三次正式彩排与故障预案演练；决赛演示故事线、PPT 与问答口径；Track D 数据责任演示。

## 7. 风险与止损

| 风险 | 早期信号 | 处理与止损 |
|---|---|---|
| Agent 改造拖延 Track A | L1 一周内无法在固定案例上跑通 | 先完成 A1 纯 UI 闭环，L1 降级为实验分支 |
| 弱项物种修不动 | 增强后 F1 仍 < 0.3 | 演示口径改为大类候选 + 谨慎拒识，不承诺具体物种 |
| 听审进度慢 | W2 末完成数 < 50% | 抽样听审 + 双人复核争议样本，先建最小真值集 |
| 演示案例验证不过 | 关键叫声不在前 20 秒 | 换备用案例或裁剪片段，重新听审 |
| 调查交互过长 | 儿童无法在一次户外任务中完成 | 决赛版保持一轮观察，第二轮必须经过真实用户验证 |
| 现场网络/模型故障 | 彩排中触发 | 走固定案例 + 离线包 + `reuse` 模式预案 |

## 8. 决策优先级

1. 可稳定演示的完整调查闭环（Track A + C）；
2. 识别结果可信、可拒识、可解释（Track B + L1）；
3. 数据责任与隐私演示（Track D）；
4. 一轮人机调查与决策轨迹的完整性（L2/L3）；
5. CLI可回放、跨入口契约一致和演示可复现（Track E）；
6. 功能数量与新增创意。
