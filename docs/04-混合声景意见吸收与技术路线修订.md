# 混合声景意见吸收与技术路线修订

> 文档状态：技术路线讨论稿 v0.1  
> 更新时间：2026-07-28  
> 背景：结合团队关于分类头、合成混音、blind source separation、target source extraction 和 TF-GridNet 的意见

## 1. 对意见的总体判断

团队提出的方向包含两个不同层次：

1. 用单物种样本合成混合录音，并训练多标签分类器判断“里面有哪些物种”；
2. 先把混合录音分离成若干声音波形，再分别识别每个波形。

第一条路线成立、数据可构造、开发成本可控，应该成为当前 MVP 的重点。第二条路线也有研究价值，但比分类难得多，现成模型多面向语音或通用声音，不能承诺在杭州自然声场景中开箱即用。

本项目不应把两个任务混为一谈。

## 2. 三类任务的区别

| 任务 | 输入 | 输出 | 是否需要生成独立波形 | 当前优先级 |
|---|---|---|---:|---|
| 多标签声音分类 | 一段混合自然录音 | 白头鹎、乌鸫、黑蚱蝉等存在概率 | 否 | P0 |
| 声音事件检测 | 一段混合自然录音 | 物种 + 出现时间段 | 否 | P1 |
| 声源分离/目标声音提取 | 一段混合自然录音 + 可选查询 | 一个或多个分离后的音频波形 | 是 | P2 |

对于“孩子录一段声音，告诉他这里面有哪些动物”，多标签分类已经足够。只有当产品明确要求“单独播放刚才那只鸟的声音”时，才真正需要声源分离或 target source extraction。

## 3. 截图中分类头方案如何落地

### 3.1 输入与标签

假设核心物种有 7 类，再加一个非目标类。每段训练录音对应一个 multi-hot 标签：

```text
[鹊鸲, 白头鹎, 乌鸫, 珠颈斑鸠, 红嘴蓝鹊, 黑水鸡, 黑蚱蝉]

只有白头鹎： [0, 1, 0, 0, 0, 0, 0]
白头鹎+乌鸫：[0, 1, 1, 0, 0, 0, 0]
乌鸫+黑蚱蝉：[0, 0, 1, 0, 0, 0, 1]
```

模型输出层使用每类独立的 sigmoid，不能使用只能选一个类别的 softmax。

### 3.2 模型结构

建议先冻结 BirdNET 声学编码器，只训练轻量多标签分类头：

```text
3 秒混合波形
→ BirdNET embedding（1024 维）
→ 可选 LayerNorm / Dropout
→ Linear 或两层 MLP
→ K 个物种 logits
→ sigmoid
→ 每个物种独立阈值
```

训练损失优先使用 `BCEWithLogitsLoss`。若类别严重不均衡，再比较 class weight、Focal Loss 或 Asymmetric Loss；不要一开始就增加复杂损失。

BirdNET-Analyzer 官方自定义训练已经支持多标签数据：文件夹名可使用逗号连接多个类，并建议加入 `noise/background/other/silence` 非事件类。[BirdNET 多标签自定义训练文档](https://birdnet-team.github.io/BirdNET-Analyzer/best-practices/training.html)

因此第一版甚至不一定要自己实现完整分类头，可先用 BirdNET-Analyzer 验证“合成混音 + 多标签训练”是否有效，再决定是否编写自定义 PyTorch 训练代码。

## 4. “原始数据不必太干净”需要修正

这个说法对分类任务只成立一半。

允许存在风声、水声和设备噪声，但必须保证：

- 主目标物种标签可靠；
- 录音中明显的其他物种不能漏标；
- 不把包含多个未知动物的录音当成单物种样本；
- 训练和测试不能来自同一原始长录音的不同切片。

如果一段所谓“白头鹎样本”里实际还有乌鸫，而标签只有白头鹎，那么合成后会产生系统性错误监督。模型会学到“乌鸫出现时标签仍然是 0”。

因此建议把数据分成三类：

| 数据类型 | 条件 | 用途 |
|---|---|---|
| A 类干净单物种 | 主叫声突出，其他物种基本没有 | 合成训练与分离监督 |
| B 类弱背景单物种 | 有环境声，但其他动物声已排除或完整标注 | 提升分类鲁棒性 |
| C 类真实混合声景 | 多物种、噪声和距离真实 | 验证、微调和最终测试 |

多标签分类可以大量使用 A/B 类合成数据；声源分离训练则更依赖 A 类，因为模型需要每个源的真实波形作为监督目标。

## 5. 合成混音数据生成方案

### 5.1 基本流程

```text
随机选择 1–3 个不同物种的单物种片段
→ 随机裁剪或时间偏移
→ 调整各源相对响度
→ 加入真实杭州背景声
→ 可选加入设备频响、轻度混响和带宽变化
→ 求和并防止削波
→ 保存混合波形、各源波形和 multi-hot 标签
```

### 5.2 每条合成样本必须保存

```text
mixture_id
source_audio_ids
source_species
source_offsets
source_gains_db
background_audio_id
background_gain_db
augmentation_config
mixture_path
stem_paths
multi_hot_target
random_seed
```

保留 `stem_paths` 很重要：即使第一阶段只训练分类，未来也能用同一批数据测试声源分离。

### 5.3 建议的第一轮变量

- 混合物种数：1、2、3；
- 每条样本时长：3 秒，与 BirdNET 窗口对齐；
- 相对响度：覆盖“主声明显”和“目标声很弱”两种情况；
- 时间关系：完全重叠、部分重叠、先后出现；
- 背景：杭州公园实录的人声、道路、风、雨、水流、空调和纯环境底噪；
- 设备变化：手机录音常见的高低频衰减和轻度压缩；
- 削波控制：混合后峰值归一，但不能把每个源先归一到完全相同响度。

不建议第一轮使用过强变调或速度变化，因为可能改变物种身份相关的频率与节奏特征。

## 6. 合成数据的主要风险

### 6.1 合成—真实域差异

简单数字相加无法完全模拟真实公园：

- 不同动物距离和方向不同；
- 树木、水面和建筑会产生不同反射；
- 手机有自动增益、降噪和压缩；
- 蝉鸣可能持续遮蔽鸟声；
- 真实物种共同出现并不是随机独立事件。

所以模型不能只在合成混音上评测。必须保留一组杭州真实混合录音，并进行人工强标注或至少完整物种标注。

### 6.2 合成泄漏

同一个原始声音不能一部分进入训练混音、一部分进入测试混音。数据划分顺序必须是：

```text
先按原始录音/录音者/地点划分 train、validation、test
→ 再在各自集合内部生成混音
```

### 6.3 置信度不是概率真值

分类头输出经过 sigmoid 后仍可能校准不良。每个物种应在验证集上单独确定阈值，并报告 precision、recall、F1 和 false positives per hour，而不是统一使用 0.5。

## 7. 是否需要先做声源分离

结论：**MVP 不需要。**

推荐主链路：

```text
原始录音
→ 3 秒滑窗
→ BirdNET 原始分类结果
→ 自定义多标签分类头
→ 时间维度聚合
→ 输出物种、置信度和最可能出现的时间段
```

这样已经可以实现：

- 告诉孩子录音中可能有哪些动物；
- 点选物种后播放对应的原始时间段；
- 用声谱图高亮该物种最可能出现的位置；
- 为多个物种分别生成科普卡。

“高亮时间段”不等于“波形分离”，但在产品体验上已经足够清晰，并且更不容易制造伪影。

## 8. 声源分离方向评估

### 8.1 Blind Source Separation

严格意义的盲源分离在不知道源类型的情况下恢复多个源。经典 ICA 通常依赖多通道观测与独立性假设；单部手机只有一个麦克风通道，而自然声源数量未知，因此问题往往欠定。

传统 NMF/时频掩码可以做基线，但不应承诺“自动分开所有动物声音”。

### 8.2 Target Source Extraction

目标声音提取比全盲分离更贴合产品：系统先知道想提取“白头鹎”或有一个参考叫声，再从混合录音中提取目标。

可能的查询形式：

- 文本：`Light-vented Bulbul call`；
- 物种 ID；
- 一段参考声音；
- BirdNET/Perch 的物种原型 embedding。

对本项目，最合理的未来路线是“先识别候选物种，再由用户点选其中一个进行目标声音增强”，而不是一次盲分出未知数量的波形。

### 8.3 TF-GridNet

TF-GridNet 是优秀的时频域分离网络，但原始研究主要针对单通道/多通道人类语音分离、去混响和语音增强。[TF-GridNet 论文](https://arxiv.org/abs/2209.03952)

需要注意：

- 它是一种架构，不是已经训练好“杭州动物声音”的模型；
- 语音预训练权重的输出源数量和声学先验与鸟、蛙、蝉不同；
- 若使用它，需要自己构造混合波形和独立 stem，重新训练或大幅微调；
- ESPnet 有 TF-GridNet 相关实现和完整语音分离训练框架，但整体较重，适合研究实验而非比赛首版。[ESPnet](https://github.com/espnet/espnet)

结论：可列为技术储备，不进入 MVP。

## 9. 更值得优先测试的开源项目

### 9.1 Bird-MixIT

- 项目：[Improving Bird Classification with Unsupervised Sound Separation](https://bird-mixit.github.io/)
- 代码与模型：[google-research/sound-separation](https://github.com/google-research/sound-separation)
- 适用：鸟声混合分离后辅助多物种分类。
- 状态：仓库已于 2026-04-19 归档，仍可下载代码和鸟声 MixIT 模型。

该研究直接处理带环境噪声和重叠鸟声的野外录音。论文报告，鸟声专用 MixIT 比通用分离模型的重构 SI-SNR 提升高出 5 dB 以上；下游分类的最佳方式不是只使用分离结果，而是对“原始音频 + 各分离通道”的分类激活取最大值。

因此若进行分离实验，推荐结构为：

```text
原始录音 ───────────────→ 分类器 ─┐
      └→ Bird-MixIT → channel 1 → 分类器 ─┤
                    → channel 2 → 分类器 ─┤→ 每物种取 max/ensemble
                    → channel N → 分类器 ─┘
```

不要把分离后的音频完全替代原始录音。

### 9.2 BioCPPNet

- 项目：[earthspecies/cocktail-party-problem](https://github.com/earthspecies/cocktail-party-problem)
- 适用：用干净动物叫声构造混合数据、训练单通道生物声学分离器。

BioCPPNet 针对猕猴、海豚和果蝠等非人类声音，仓库包含 `DataMixer.py`、数据生成、分类器、分离器、PIT 损失和评估代码，和团队提出的“单源样本混合训练”思路最接近。[BioCPPNet 论文与代码说明](https://www.nature.com/articles/s41598-021-02790-2)

局限是代码年代和物种不同，适合作为数据构造与损失函数参考，不代表可直接处理杭州鸟蝉混合声。

### 9.3 AudioSep

- 项目：[Audio-AGI/AudioSep](https://github.com/Audio-AGI/AudioSep)
- 许可：MIT；模型权重仍需单独核对分发条款。
- 适用：用自然语言查询提取目标声音，例如 `cicada buzzing` 或 `bird call`。

AudioSep 是开放域文本条件声音分离模型，官方提供 32 kHz 推理、Windows 环境文件、预训练权重和微调入口。它适合做零样本快速实验，但必须实测其是否能区分具体中国鸟种；模型在通用“鸟鸣”层面有效，不等于能准确提取白头鹎。

### 9.4 FUSS / MixIT

- 项目：[google-research/sound-separation](https://github.com/google-research/sound-separation)
- 作用：通用声音分离数据、MixIT 无监督/弱监督分离和合成混音参考。

仓库提供 FUSS、通用 MixIT 和鸟声 MixIT，但已经归档。可用于复现实验和理解数据生成，不建议把它作为长期依赖的核心服务。

## 10. 修订后的技术架构

### 阶段 A：比赛 MVP

```text
手机录音
→ 格式统一与 3 秒滑窗
→ BirdNET 默认多物种结果
→ 杭州 7 类自定义多标签分类头
→ 原始/自定义结果融合
→ 每物种阈值与 unknown 判定
→ 返回物种列表、置信度、时间段、科普卡
```

### 阶段 B：混合声景增强

```text
A/B 类单物种数据
→ 合成 1–3 源混音
→ 多标签训练
→ 杭州真实混合声景微调/校准
→ 声音事件时间定位
```

### 阶段 C：实验性目标提取

```text
识别候选物种
→ 用户点选目标
→ AudioSep / Bird-MixIT / 自定义 TSE
→ 与原始音频共同送入分类器复核
→ 仅作为“AI 增强试听”，明确标注可能产生失真
```

### 阶段 D：研究型分离

只有在积累足够杭州 stem 与真实混合数据后，才比较 BioCPPNet、TF-GridNet 或其他分离网络。

## 11. 第一轮实验矩阵

| 实验 | 训练数据 | 模型 | 目标 | 是否立即做 |
|---|---|---|---|---:|
| E0 | 公开/本地单物种 | BirdNET 默认模型 | 建立单物种基线 | 是 |
| E1 | 合成 1–3 物种混音 | BirdNET 多标签自定义头 | 检测混合中有哪些物种 | 是 |
| E2 | 杭州真实混合录音 | E1 模型 | 测量合成域差异 | 是 |
| E3 | 合成混音 + stems | BioCPPNet | 验证能否分出波形 | 之后 |
| E4 | 杭州真实混合录音 | Bird-MixIT + 分类器 | 看分离是否提升分类 | 之后 |
| E5 | 混合录音 + 英文物种描述 | AudioSep | 测试目标提取零样本能力 | 可快速试验 |
| E6 | 大规模合成 + 真实 stems | TF-GridNet | 自建动物声分离模型 | 暂缓 |

## 12. 评估指标

### 多标签分类

- 每类 precision、recall、F1；
- macro/micro F1；
- mean average precision；
- 每小时误报数；
- 单物种、双物种、三物种分别统计；
- 目标声相对较弱时的召回率；
- 合成测试与杭州真实测试的差距。

### 声音事件检测

- event-based F1；
- segment-based F1；
- 时间定位误差。

### 声源分离

- SI-SDR improvement；
- 下游分类 F1 是否提升；
- 原始音频、分离音频和 ensemble 三者比较；
- 人工听评是否出现明显伪影或物种特征破坏。

对本项目而言，下游物种识别是否提升比“声音主观听起来更干净”更重要。

## 13. 最终建议

吸收这些意见后，项目的技术亮点可以升级为：

> 面向真实城市自然声景，利用单物种样本自动构造多物种混合训练数据，在生物声学预训练特征上训练杭州本地多标签分类器；系统不仅识别一个最显著声音，还能输出同一录音中多个物种及其出现时间。声源分离作为增强模块，用于改善低信噪比识别和目标声音试听。

比赛中可以讲“研究了生物声学鸡尾酒会问题”，但 Demo 主承诺应保持为“混合声景多物种识别”，不应在没有实测前承诺“完全分离每种动物的原始叫声”。
