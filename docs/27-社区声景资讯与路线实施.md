# 社区声景、UGC、每日资讯与探索路线实施

> 文档状态：社区2.0实施中
> 更新时间：2026-08-25

## 1. 产品目标

将“共听杭州”从区级声音帖子列表升级为：

```text
今日自然声讯
→ 公园/分区声景
→ 真实调查与AI作品社区
→ 家庭探索路线
→ 新调查继续补充社区数据
```

对外统一使用“社区声景观察趋势”，不输出未经本地验证的生态健康总分。

## 2. 第一阶段已实现

### 三个试点公园

- 杭州植物园：灵峰入口、林下步道、水生植物区外围；
- 西溪湿地：湿地步道、芦苇外围、林地岛外围；
- 太子湾公园：中心草地区、溪流步道、林缘缓坡。

所有位置均为公园/分区公开中心点，不代表录音精确位置。

### 社区帖子证据字段

```text
park_id / zone_id / site_id
sampling_mode
sampling_effort
audio_quality
ecology_eligible
```

无公园绑定、音质不可用或只有AI媒体的帖子可以展示，但不进入公园声景聚合。

### UGC媒体资产

社区帖子可以追加：

```text
image / video / thumbnail
original / ai_generated / composed
provider / model / moderation_status
```

图片上限25MB，视频第一版仅支持MP4。撤回帖子时同时删除底层真实音频和展示媒体。

### 声景快照

当前快照包含：

- 有效帖子数；
- 独立观察者数；
- 声音类型分布；
- 人工确认数；
- 观察日覆盖与采样方式分布；
- 与上一周期相比的社区记录活动趋势；
- 每个公开分区的有效观察数、独立观察者和声音类型；
- 数据充分度：low / medium / high；
- 固定科学边界说明。

数据充分度不是生态好坏。当前门槛：

```text
high   >=20条且>=8位独立观察者
medium >=6条且>=3位独立观察者
low    其他情况
```

只有当前周期和上一周期都达到至少6条有效记录时，才展示`higher / similar / lower`活动趋势；否则输出`insufficient`。该趋势描述社区声音记录活动，不等同于动物数量变化。

### 每日自然声讯

第一版使用确定性模板，根据声景快照生成：

- 标题；
- 数据事实；
- 可能原因；
- 不确定性；
- 今日观察任务。

数据不足时明确邀请用户补充，不把“缺少上传”解释为“缺少动物”。

## 3. 当前API

```text
GET /api/community/parks
GET /api/community/sites?park_id=...
GET /api/community/parks/{park_id}/ecology-snapshot?days=7
GET /api/community/parks/{park_id}/daily-brief?days=7
GET /api/community/parks/{park_id}/routes
POST /api/community/posts/{post_id}/media
```

原有区级接口、帖子、协助、授权和撤回保持兼容。

## 4. 数据库迁移

默认只读查看目标与迁移状态：

```powershell
uv run python scripts/community_migrate.py
uv run python scripts/community_migrate.py --json
```

确认发布窗口后执行：

```powershell
uv run python scripts/community_migrate.py --apply --confirm-host <完整数据库主机名>
```

CLI会自动识别已手工执行但尚未登记的`001`，记录SHA-256基线；随后在事务和advisory lock保护下执行`002`，并进行迁移后结构验收。

迁移会：

- 扩展`community_posts`；
- 重建`community_public_posts`公开视图，使新增证据字段能够被线上API读回；
- 创建`community_sites`；
- 创建`community_media_assets`；
- 写入9个试点分区；
- 创建公园/分区和媒体索引。

## 5. Flutter当前体验

已贯通：

- 首页“今日自然声讯”；
- 三个试点公园切换；
- 公园分区声景图，展示各公开分区的社区发现数量并支持点选筛选；
- 发布时选择公园与公开分区；
- 帖子图片/视频缩略图；
- 从作品册筛选同一动物的故事视频，由用户选择后随探索卡上传；
- 先发布真实声音、再上传展示作品，作品失败只重试媒体，不重复发帖；
- 数据充分度与声景趋势卡；
- 每个公园一条审核路线及分站倾听任务；
- 路线开始、逐站任务勾选、完成进度与本机持久化。

### 探索路线

第一版已采用审核路线，不自动生成任意步行路径：

- 每个公园1–2条路线；
- 3–5个停靠点；
- 路线时长、年龄和安全标签；
- 每站最近声音线索和倾听任务；
- 社区近期数据只调整推荐顺序。

当前路线完成状态保存在本机，不上传儿童轨迹或精确坐标。尚未接入真实地图导航和基于定位的自动到站判断；决赛版采用用户主动确认任务，避免为了“打卡”收集不必要的位置数据。
