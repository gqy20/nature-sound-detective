# 自然声探员：技术实施方案与项目推进计划

> 文档状态：执行版 v0.1  
> 更新时间：2026-07-28  
> 项目地点：杭州  
> 初赛截止：2026-08-13  
> 团队规模：2 人

## 1. 项目目标

在初赛前交付一个可在手机浏览器演示的完整闭环：儿童录制 5–15 秒杭州公园声景，系统识别其中一个或多个目标物种，展示证据片段与不确定性，生成儿童科普卡、声音题和自然声音邮票，并能制作一张保留原声的音乐明信片。

项目的技术重点不是追求覆盖尽可能多的物种，而是证明三个能力：

1. 能处理真实环境中多种动物与噪声同时出现的录音；
2. 能把识别结果转化为可靠、有趣的儿童自然教育体验；
3. 能在数据不足和模型不确定时诚实拒识，并保持产品流程可用。

## 2. 初赛范围冻结

### 2.1 目标类别

BirdNET 已覆盖的 6 种杭州常见鸟类：

- 鹊鸲；
- 白头鹎；
- 乌鸫；
- 珠颈斑鸠；
- 红嘴蓝鹊；
- 黑水鸡。

自定义补充类别：

- 黑蚱蝉。

系统还必须有 `unknown/background` 拒识能力。小䴙䴘、夜鹭作为鸟类备选，布氏泛树蛙放到第二阶段。

### 2.2 初赛必须完成

- 手机网页录音、回放和上传；
- 音频转码、切窗和质量提示；
- 6+1 类多标签识别与 unknown 拒识；
- 每个候选物种的置信度和有效时间段；
- 人工审核知识库驱动的儿童科普卡；
- 一道听音题和一枚声音邮票；
- 原声与生成背景乐合成的音乐明信片；
- 三段可离线重复演示的样例。

### 2.3 暂不进入主链路

- 完整动物声音分离和波形重建；
- 上百种开放世界识别；
- 生境健康度结论；
- 公开社区、班级系统和精确声音地图；
- 原生安卓/iOS 客户端；
- 生成模型重构或伪造动物叫声。

## 3. 总体技术架构

```text
移动端网页
MediaRecorder / Web Audio / WaveSurfer
        │
        ▼
FastAPI 上传与任务接口
        │
        ▼
FFmpeg 转单声道 WAV、响度检查、3 秒滑窗
        │
        ├── BirdNET 原始分类分数：6 种鸟类稳定基线
        │
        └── BirdNET embedding：杭州 7 类多标签分类头
                    │
                    ▼
        跨窗口平滑 + 逐类阈值 + unknown/background
                    │
                    ▼
        物种候选、置信度、证据时间段、模型版本
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
结构化知识库   声音题/邮票   原声音乐明信片
        │
        ▼
大模型只负责儿童化表达，不生成未经审核的事实
```

初赛默认保留两套推理结果：BirdNET 原始输出作为兜底，多标签分类头作为主实验。前处理也保留原音，不让降噪或分离成为唯一输入。

## 4. 技术栈建议

| 环节 | 首选 | 说明 |
|---|---|---|
| 前端 | React 或 Vue 3 + Vite + TypeScript | 选择团队最熟悉的一套，不为框架换型耗时 |
| 手机录音 | MediaRecorder + Web Audio API | 兼容性实测覆盖安卓 Chrome 与 iPhone Safari |
| 波形展示 | WaveSurfer.js | 播放、波形与证据区间标注 |
| 后端 | Python 3.11 + FastAPI | Python 3.12 下 BirdNET/TensorFlow 已出现异常，暂不使用 |
| 异步任务 | FastAPI BackgroundTasks | Demo 足够；并发增加后再换 RQ/Redis |
| 音频处理 | FFmpeg + librosa 或 torchaudio | 转码、切窗、特征和合成混音 |
| 鸟类基线 | BirdNET | 6 种核心鸟已确认在标签集中 |
| 多标签模型 | BirdNET embedding + 小型 MLP + sigmoid | 7 个独立输出，允许同时命中多类 |
| 数据库 | SQLite | 存任务、结果、邮票和模型版本 |
| 文件存储 | 本地目录 | 初赛不引入对象存储运维成本 |
| 科普内容 | 结构化 JSON + 大模型改写 | 事实与表达分离 |
| 明信片 | 原声 + 生成背景乐 + FFmpeg | 永久标明原始、增强和生成部分 |
| 视频 | 模板式合成优先 | 生成视频模型仅做展示增强 |

## 6. 数据流水线

### 6.1 数据分层

| 层级 | 内容 | 用途 |
|---|---|---|
| A：干净单源 | 目标动物占主导、标签明确 | 训练分类头、构造混音 |
| B：弱背景单源 | 有轻微风声、远处人声或其他声 | 提升鲁棒性 |
| C：真实混合声景 | 同时出现多个物种和城市噪声 | 独立验证，不用于早期调参 |
| N：负样本 | 风、雨、人声、交通、脚步、非目标动物 | unknown/background 与误报控制 |

来源优先级：团队杭州实录与已授权校内素材 > Xeno-canto 逐条许可素材 > iNaturalist 可核验音频 > 其他明确授权数据库。不能批量下载后再补来源；每个文件进入项目时就记录来源链接、作者、许可、物种、地点、日期、设备和质量等级。

### 6.2 处理规则

1. 原始音频只读保存，不覆盖；
2. 统一转成单声道 WAV，保留原采样率信息，模型输入按其要求重采样；
3. 人工确认标签和主要叫声时间段；
4. 先按原始录音/录音者划分 train、validation、test，再切窗与混音，防止数据泄漏；
5. 默认切 3 秒窗口，推理步长 1.5 秒；
6. 所有增强参数和随机种子写入元数据；
7. 测试集不做挑选式删样，不按模型表现反复修改标签。

### 6.3 第一版数据目标

- 每个目标类至少 30 条独立原始录音，优先达到 50 条；
- 每类至少 10 条不同手机或不同环境的杭州实录；
- 至少 50 条负样本，覆盖人声、风、雨、交通和非目标动物；
- 合成 8,000–15,000 个训练窗口、1,000–2,000 个验证/测试窗口；
- 混音比例约为单物种 40%、双物种 40%、三物种 20%；
- 单源相对增益随机化，并叠加不同强度背景声、时间偏移和轻微设备响应模拟；
- 至少 30 条人工逐段标注的杭州真实混合声景作为最终独立测试集。

如果 7 月 31 日仍无法为某类获得至少 20 条可用独立录音，该类退出初赛主模型或换成备选物种，不用低质量伪标签硬撑类别数。

## 7. 模型实验路线

### E0：BirdNET 基线

- 使用杭州经纬度和夏季日期作为弱先验；
- 固定 3 秒窗口并保存所有类别分数；
- 评估 6 种鸟、负样本和真实手机录音；
- 输出逐类精确率、召回率、F1、误报样本和推理耗时。

E0 是产品兜底，不等待自定义训练完成。

### E1：7 类多标签分类头

- 输入 BirdNET embedding；
- 输出 7 个独立 logit，经 sigmoid 转概率；
- 使用 `BCEWithLogitsLoss`，按类别不平衡设置权重；
- 用合成单/双/三物种声景训练；
- 在验证集上为每一类单独选择阈值，不统一使用 0.5；
- 不把 unknown 做成与物种互斥的普通类别，主要通过背景负样本与“所有类别均低于阈值”实现拒识。

### E2：真实声景验证与融合

- 在杭州手机实录上比较 BirdNET 原始分数、E1 和两者融合；
- 分别报告单物种、双物种、三物种与纯背景表现；
- 检查合成数据到真实数据的性能落差；
- 逐类调整阈值，优先压低对儿童造成误导的高置信误报；
- 固化模型、阈值、类别表和评估报告为同一个版本。

### E3：声源分离增强实验

仅在 E1/E2 已完成且仍有时间时执行：

1. 先测试 Bird-MixIT、AudioSep 或 BioCPPNet 是否能增强目标证据；
2. 分离音频只作为附加输入，与原音识别结果融合；
3. 以识别 F1 是否提升为主要判断，不以人耳“更干净”为标准；
4. TF-GridNet 只有在拥有足够单源/混合训练对、重建目标和训练资源时才研究；
5. 分离没有稳定提升就停止，不进入初赛主链路。

## 8. 在线推理逻辑

1. 接收 5–15 秒录音，检查格式、时长和音量；
2. FFmpeg 转码，生成 3 秒窗口，步长 1.5 秒；
3. 每个窗口运行 BirdNET，提取原始分数和 embedding；
4. 多标签分类头输出 7 类概率；
5. 融合两路结果，并对相邻窗口平滑；
6. 使用逐类阈值判断物种是否出现；
7. 连续命中的窗口合并为证据时间段；
8. 最多展示 3 个最可信候选，但不强迫凑满；
9. 所有目标类都低于阈值时返回 unknown，并提示重新录制；
10. 地点、季节先验只调节排序，不能推翻强音频证据；
11. 保存模型版本、阈值版本、原始结果和最终结果，保证可复现。

## 9. 接口草案

### `POST /api/recordings`

上传音频与可选地点、时间，返回任务编号。

### `GET /api/jobs/{job_id}`

返回 `queued`、`processing`、`completed` 或 `failed`，以及可展示的进度文本。

### `GET /api/jobs/{job_id}/result`

```json
{
  "status": "completed",
  "recording_id": "rec_001",
  "model_version": "hangzhou-multilabel-v1",
  "quality": {"usable": true, "warnings": ["distant_voice"]},
  "detections": [
    {
      "species_id": "copsychus_saularis",
      "name_zh": "鹊鸲",
      "confidence": 0.86,
      "intervals": [{"start": 1.5, "end": 6.0}]
    }
  ],
  "unknown": false
}
```

### 内容接口

- `GET /api/species/{species_id}`：审核后的科普字段；
- `POST /api/postcards`：生成声音明信片；
- `GET /api/stamps`：读取当前用户的声音邮票。

## 10. 前端最小页面

1. **首页**：一句话价值、开始探索、已有邮票；
2. **录音页**：倒计时、音量、波形、录音质量提示；
3. **分析页**：明确进度，不伪造模型思考过程；
4. **结果页**：多个候选物种、置信度、证据片段、重录入口；
5. **探索成果页**：科普卡、声音题、邮票、音乐明信片。

手机端必须支持无账号体验；儿童姓名、精确位置和原始录音默认不公开。

## 11. 知识库与生成内容

每个物种使用一份人工审核 JSON，至少包含：

```json
{
  "species_id": "copsychus_saularis",
  "scientific_name": "Copsychus saularis",
  "name_zh": "鹊鸲",
  "sound_description": "待生态人员审核",
  "vocalization_purposes": [],
  "habitat": [],
  "active_time": "",
  "hangzhou_season": "",
  "observation_tip": "",
  "fun_fact": "",
  "sources": [],
  "review_status": "draft"
}
```

大模型只能根据这些字段改写为 6–8 岁或 9–12 岁表达、生成题目和旁白；缺失事实必须省略或明确“不确定”，不能自行补全。比赛现场预先缓存审核后的稳定文案，避免 API 波动阻断 Demo。

## 12. 验收标准

### 12.1 模型验收

- 报告每类 precision、recall、F1 和 micro/macro-F1；
- 单、双、三物种混音分别评估；
- 至少 30 条纯背景/非目标录音测拒识；
- 至少 30 条杭州手机混合录音做独立测试；
- 数据按原始录音或录音者隔离，无切片泄漏；
- 6 种鸟中至少 5 种达到可稳定演示水平，黑蚱蝉不足时可明确标注实验类别；
- 所有演示结果可追溯到模型与阈值版本。

不预先写死虚高准确率。数据完成后再设目标值，答辩同时展示失败案例和改进边界。

### 12.2 产品验收

- 安卓 Chrome 与 iPhone Safari 至少各实测一台；
- 正常网络下目标 15 秒内返回识别结果；
- unknown 能提供重录建议，而不是硬猜；
- 同一录音可展示多个候选卡片和各自证据段；
- 原始、增强、生成声音在 UI 中有明确标签；
- 三段固定样例连续演示三次无失败；
- 网络或生成模型失败时仍能完成识别、科普、答题和集邮；
- 至少完成 5 组亲子或替代用户可用性测试。

## 15. 日常项目管理

任务看板只保留 `todo / doing / blocked / done` 四种状态，每人同时最多一个 `doing`。每日同步四句话：昨天完成了什么、今天交付什么、阻塞是什么、需要对方确认什么。

每个实验必须保存：

- 数据版本与样本数量；
- 许可证台账完整率；
- 代码提交或配置版本；
- 逐类和多标签指标；
- 三个代表性成功样本；
- 三个失败样本及原因；
- 下一步继续、回退或停止的决定。

## 16. 风险与止损

| 风险 | 早期信号 | 处理与止损 |
|---|---|---|
| BirdNET 在 Windows 运行异常 | Python 3.12/TensorFlow 崩溃 | 固定 Python 3.11；仍失败则切 WSL，不继续修 3.12 |
| 黑蚱蝉数据不足 | 7 月 31 日不足 20 条独立录音 | 标记实验类或退出主模型，不用伪标签补数 |
| 合成混音过拟合 | 合成集高、杭州实录低 | 增加真实背景与手机响应；G1 回退 BirdNET |
| 多标签误报多 | 背景录音频繁命中 | 增加 N 类、逐类阈值、连续窗口确认 |
| 降噪损伤虫鸣/鸟鸣 | 听感变清晰但 F1 下降 | 原音保持主输入，降噪仅做可关闭对照 |
| 分离研究耗时 | 两天内无法复现或无下游提升 | 停止 E3，不影响主链路 |
| 数据许可不清 | 缺作者、链接或条款 | 不进入训练集和公开 Demo |
| 生成服务不稳定 | 超时、限流、内容漂移 | 缓存审核文案；视频和音乐失败可降级 |
| 手机录音兼容问题 | Safari 无法上传/播放 | 提前真机测试，并保留文件上传入口 |
| 范围持续膨胀 | 新增地图、社区、健康度需求 | 统一记入赛后清单，初赛不开发 |

## 17. 决策优先级

遇到冲突时按以下顺序取舍：

1. 可稳定演示的完整用户闭环；
2. 识别结果可信、可拒识、可解释；
3. 杭州真实场景证据；
4. 多标签模型的技术创新；
5. 声源分离、视频生成等展示增强；
6. 物种数量和功能数量。
