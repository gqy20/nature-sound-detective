# 比赛演示与验收清单

## 演示主线

建议把现场演示控制在 3 分钟内：

1. 孩子在杭州公园录下一段自然声音；
2. 系统给出声音大类、鸟种候选、判断依据和不确定性；
3. 系统生成儿童能理解的科普卡片与继续观察的问题；
4. 播放已生成的旁白、Music 3.0 音乐和竖屏自然短片；
5. 保存到声音册，说明它可以形成孩子长期的自然成长记录。

核心表达不是“AI 猜中一个名称”，而是“把一次户外倾听变成可理解、可继续观察、可带回家的亲子自然体验”。

## 固定演示资产

正式展示前准备三组已人工确认的杭州录音：

| 场景 | 用途 | 最低要求 |
|---|---|---|
| 清晰常见鸟鸣 | 展示 BirdNET 候选物种 | 目标鸟叫位于前 20 秒，现场实测通过 |
| 风和树叶或流水 | 展示非物种自然声音 | Qwen 大类判断稳定，科普文本已审核 |
| 混合且较嘈杂的公园声景 | 展示不确定性 | 系统应谨慎输出多个线索，而非强行确认物种 |

每组都保留原始录音、识别结果截图、旁白 MP3、20 秒音乐片段和最终 MP4。比赛现场使用 `WAN_VIDEO_MODE=reuse`，不等待视频服务，也不产生新的费用。

首批候选已记录在 `data/metadata/competition_demo_candidates.csv`。当前三条均为 `human_verified=no`、`rehearsal_status=pending`，完成听音和至少三次完整彩排前不能称为正式演示样本。

## 故障预案

- 网络正常：现场运行识别，生成内容使用已有视频画面；
- 模型超时：立即切换“试用示例”并解释异步任务设计；
- 网络断开：播放本地固定案例和最终成片；
- MiniMax 失败：使用本地自然原声混音，界面明确标注来源；
- 视频失败：音乐和旁白仍可单独播放，声音卡片不受影响；
- 浏览器刷新：从声音册重新打开服务端任务结果。

## 隐私与安全说法

- 原始录音只上传到当前服务用于识别，并在默认 24 小时后清理；
- MiniMax 只接收音乐提示词与旁白文本，不接收孩子的原始录音；
- Wan2.7 只接收画面提示词；
- 不要求儿童姓名、照片或精确定位；
- 内容提示词禁止追逐、捕捉、触摸动物，并避免生成儿童正脸。

## 正式验收门槛

- `uv run pytest -q` 全部通过；
- `uv run python scripts/audit_evaluation_readiness.py` 达到人工样本门槛；
- 6 种核心鸟类分别报告候选召回率，不把弱标签当准确率；
- 声音大类报告各类样本数、命中率和主要混淆；
- 390 px 移动端完成录音、查看结果、播放媒体、下载和声音册回访；
- `mock`、`reuse`、`live` 三种视频模式来源标注正确；
- 仅在最终验收执行一次 Live 视频生成，并记录任务 ID、耗时和费用。

## 答辩时主动承认的边界

- BirdNET 当前只覆盖杭州 MVP 六种常见鸟类；
- 蛙类和昆虫目前以大类识别为主，不承诺具体物种；
- 混合声景存在遮蔽，系统展示候选和不确定性，不替代专家调查；
- 当前是面向亲子教育的创意工具，不是生态监测仪器或科研结论系统。
