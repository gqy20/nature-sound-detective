# 自然声探员：字体系统调研与优化建议

更新日期：2026-07-31

## 1. 结论

当前页面的主要问题不是缺少“更特别的字体”，而是字体规则不稳定：不同系统会显示不同的中文字形，若干非标准字重无法被现有中文字体真实呈现，中文标题字距和行高又压得过紧。

建议分两步处理：

1. 先用零额外下载成本的系统字体方案，统一字号、标准字重、行高和字距。
2. 比赛展示版再评估自托管思源黑体；只有在品牌效果确实明显时，才为少量标题加入霞鹜文楷。

不建议现阶段直接使用 MiSans 作为网页内嵌字体：其授权不是 OFL，官方协议要求注明使用且限制字体文件再分发，网页嵌入场景需要进一步做法务确认。

## 2. 当前实现审计

当前全局字体为：

```css
"Segoe UI", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif
```

### 2.1 跨平台表现不一致

- Windows 首先选择 Segoe UI；中文字符不足时再回退到微软雅黑。
- macOS 通常会使用苹方显示中文。
- Android、Linux 是否具备这些字体并不确定，会继续使用系统回退。
- 因而同一行中的西文、数字和中文可能来自不同字体，比赛电脑和手机上的宽度、字重、换行都可能变化。

### 2.2 使用了大量非标准字重

当前 CSS 使用 `720`、`750`、`760` 等字重。可变字体能够表达这种连续字重，但微软雅黑、苹方等回退字体不一定提供对应实例；浏览器会寻找邻近字重或进行合成，最终效果不可预测。

建议产品只使用四级字重：

| 角色 | 建议字重 |
|---|---:|
| 正文、说明 | 400 |
| 输入框、次级按钮 | 500 |
| 标签、主要按钮、小标题 | 600 |
| 主标题、关键结果 | 700 |

### 2.3 中文主标题过度压缩

桌面端主标题为 `letter-spacing: -0.065em`。当前实测约为 `-3.17px`；窄屏下仍约为 `-2.47px`。这种紧排常用于拉丁大标题，但中文方块字内部本就密集，继续压缩会让标题显得拥挤、笔画黏连。

建议：

- 中文大标题字距使用 `-0.02em` 至 `0`。
- 行高由当前 `1.02–1.03` 调整为 `1.08–1.15`。
- 不在 HTML 中永久写死 `<br>`；优先使用 `text-wrap: balance`，由宽度决定换行。

### 2.4 辅助文字偏小

录音提示当前为 `12px`，页脚为 `13px`。它们包含麦克风权限、识别局限等重要信息，不应被当作装饰性脚注。

建议移动端正文下限为 `14px`，只有时间、数据标签等短文本可以使用 `12–13px`。

### 2.5 正文和控件缺少统一行高

正文局部设置了较舒适的 `1.7–1.8`，但全局仍是 `normal`，按钮、标签、导航和输入框会由各平台自行决定行高。建议为全局、按钮和标签分别建立明确的行高令牌。

## 3. 字体候选

| 方案 | 气质 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| 系统中文字体栈 | 克制、原生 | 零下载、加载最快、适合手机 MVP | 跨平台字形不完全一致 | 第一阶段首选 |
| 思源黑体 / Noto Sans SC | 清晰、现代、可靠 | 开源 OFL、简体中文字形完整、适合界面和科普正文 | CJK 文件较大，需要 WOFF2、子集化和缓存 | 比赛展示版首选 |
| 霞鹜文楷 | 手写、自然、故事感 | OFL、适合儿童故事和自然观察语气 | 作者也提示不适合大段正文；字库较大；字重有限 | 仅用于短标题或观察问题 |
| 思源宋体 / Noto Serif SC | 书本、科普、编辑感 | 适合故事标题和较正式的科普卡片 | 小字号和按钮不如黑体清晰，可能显得偏成人 | 可用于结果标题，不用于界面正文 |
| MiSans | 现代、圆润、移动端 | 字形友好、具备多字重 | 非 OFL；官方协议要求注明且限制字体文件再分发 | 暂不内嵌 |

## 4. 推荐字体架构

### 4.1 第一阶段：不增加字体资源

```css
:root {
  --font-ui: "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC",
    "Noto Sans CJK SC", "Source Han Sans SC", system-ui, sans-serif;
}

body {
  font-family: var(--font-ui);
  font-size: 16px;
  line-height: 1.65;
  font-synthesis: none;
}
```

把中文字体放到 Segoe UI 之前，可以减少中西文混排时频繁回退。Windows 优先使用微软雅黑 UI，macOS 在找不到微软雅黑时回退到苹方。实机检查发现部分 Windows 环境可能只安装了 `PingFang SC Thin`，若把苹方放在最前面，粗体标题会被错误渲染成细体，因此这里采用 Windows 字体优先的顺序。此方案加载最快，但无法保证每个平台完全相同。

### 4.2 第二阶段：比赛展示版

自托管思源黑体简体中文 WOFF2，仅保留实际需要的 `400/500/600/700`，或使用支持该范围的可变字体文件：

```css
@font-face {
  font-family: "Nature Sans";
  src: url("/static/fonts/source-han-sans-sc.woff2") format("woff2");
  font-style: normal;
  font-weight: 400 700;
  font-display: swap;
}
```

由于 AI 会生成不可预知的中文内容，不能只对子集保留首页固定文案。应至少覆盖常用简体中文字符，并验证缺字回退。字体文件应自托管，避免比赛现场依赖境外字体 CDN。

### 4.3 可选品牌字体

如果需要更强的亲子故事感，可以让霞鹜文楷只承担：

- 首页主标题；
- 结果卡标题；
- “继续观察”的问题句。

按钮、输入框、证据说明和长段科普正文继续使用黑体。整个产品最多两套字族。

## 5. 建议的字号系统

| 角色 | 桌面端 | 移动端 | 行高 | 字重 | 字距 |
|---|---:|---:|---:|---:|---:|
| 首页 H1 | 64px | 42px | 1.10 | 700 | -0.02em |
| 页面 H2 | 40px | 30px | 1.18 | 700 | -0.015em |
| 卡片 H3 | 24px | 22px | 1.30 | 600 | 0 |
| 儿童科普正文 | 18px | 17px | 1.80 | 400 | 0.01em |
| 普通正文 | 16px | 16px | 1.70 | 400 | 0 |
| 按钮 | 16px | 16px | 1.25 | 600 | 0 |
| 标签 | 13px | 13px | 1.40 | 600 | 0.04em |
| 辅助说明 | 14px | 14px | 1.60 | 400 | 0 |

不建议为中文标签继续使用 `.08em` 的宽字距；它会让短标签显得零散。

## 6. 与优秀网站做法的关系

Awwwards 的声音类、叙事类网站常用“大标题建立情绪 + 克制正文保证任务完成”的组合。真正有效的是角色差异，而不是堆叠很多字体。Editorial New 的案例展示了可变字体通过字重、字号和字距形成动态表现；Sound City Project 则把字体放在声音体验之后，保持了简洁的信息层级。

对本项目而言，应把字体表达集中在首页标题、声音发现标题和观察问题上；录音按钮、权限提示和识别依据必须优先保证清晰。

## 7. 性能与无障碍要求

- 使用网页字体时优先 WOFF2，并设置 `font-display: swap` 或根据测试选择 `optional`。
- 只预加载首屏真正使用的一份字体，不预加载全部字重。
- 测试字体交换前后的布局偏移，避免标题换字体后重新断行。
- 页面在用户增加行距、字距和词距时不能裁切内容或遮挡按钮。
- 去掉写死的标题换行后，检查 320px、390px、768px 和桌面宽度。
- 重要说明不低于 14px，并验证弱视、系统字体放大和 200% 页面缩放。

## 8. 推荐实施顺序

1. 先修改字体栈、标准字重、主标题字距和行高。
2. 将 12px 的权限提示提升到 14px。
3. 去掉主标题固定换行，加入平衡换行并回归四个断点。
4. 用 Windows、Android、iOS 各截图一次，判断系统字体方案是否已经足够。
5. 若比赛演示机上的差异仍明显，再自托管思源黑体 WOFF2。
6. 最后才比较“全黑体”和“黑体 + 文楷短标题”两个视觉版本。
