# 第二阶段统一标注与 BirdNET 基线

## 1. 阶段目标

第二阶段解决两个问题：

1. 把 `data/` 根目录原有的物种录音接入人工复核流程，而不是只依赖文件名；
2. 用 BirdNET 对杭州核心物种做可复现的录音级基线，并生成待人工确认的三秒片段。

## 2. 统一标注队列

当前队列共 76 条：

| 数据来源 | 数量 | 主要用途 |
|---|---:|---|
| 既有物种录音 | 26 | 正样本与混合物种候选 |
| Freesound 公开预览 | 50 | 背景、unknown 与混音增强候选 |

既有录音保持原位置和原文件名，不移动、不重命名、不删除。脚本从文件名解析弱标签，使用 SHA-256 识别重复内容，并为每条录音生成稳定的 ASCII `item_id`。

统一标注页面：

```powershell
uv run python scripts/prioritize_freesound_review.py
uv run python scripts/prepare_unified_review.py
uv run python scripts/review_freesound.py --port 8767
```

标注结果分别写回 `existing_review_queue.csv` 和 `freesound_review_queue.csv`。重新生成机器标签时保留已有 `human_*` 字段。

## 3. 完整性与音质

- 26 条既有录音全部可完整解码；
- 21 条为可用音量候选；
- 4 条过静，需要试听判断；
- 1 条稀疏或接近静音，需要试听判断；
- 两个 `XC1145570` 文件内容完全相同，必须作为同一个源组处理。

底层 MP3 解码器批量运行时曾输出警告；逐文件隔离解码后 26 条均正常，因此没有将其误判为损坏文件。

## 4. BirdNET 2.4 基线

运行命令：

```powershell
uv run python scripts/run_stage2_birdnet.py
```

扫描范围为 26 条既有录音，总时长约 34 分钟。正式录音级弱标签评估只纳入 Xeno-canto 来源、文件名主标签属于核心物种且未标记混合声景的 7 条录音。

| 指标 | 结果 |
|---|---:|
| 评估录音 | 7 |
| 唯一音频 | 7 |
| 置信度阈值 0.25 的召回率 | 71.43% |
| 置信度阈值 0.50 的召回率 | 57.14% |

按物种计数：珠颈斑鸠 3 条、乌鸫 3 条、白头鹎 1 条。两个乌鸫文件名正样本未被 BirdNET 确认，不能直接视为模型错误，需要先试听验证标签和有效发声区间。

这些结果不是正式准确率：文件名只是弱标签，且样本来自公开录音而非杭州手机实录。

## 5. 候选片段与数据划分

BirdNET 以 0.25 为候选阈值生成三秒片段，背景候选来自已筛选的 Freesound 录音。

| 标签 | 候选片段数 |
|---|---:|
| 珠颈斑鸠 | 72 |
| 白头鹎 | 46 |
| 乌鸫 | 1 |
| background | 23 |
| 合计 | 142 |

按源文件哈希分组后：训练 66 段、验证 37 段、测试 39 段，共 28 个源组，跨集合泄漏为 0。

同一源录音的所有片段只能进入同一集合。划分仍是候选划分；人工复核删除或修改有效区间后必须重新生成。

## 6. 当前结论

流程已经从“文件名分类”推进到“机器定位候选片段 + 人工试听确认”。当前数据可以用于验证流水线，但不能直接训练正式六分类模型：

- 只有珠颈斑鸠、白头鹎、乌鸫拥有核心正样本；
- 乌鸫只有一个置信度超过 0.25 的候选片段；
- 鹊鸲、红嘴蓝鹊、黑水鸡没有正样本；
- 缺少独立的杭州手机现场测试集；
- 50 条 Freesound 背景声尚未完成人工隐私和类别审核。

## 7. 下一步门槛

在训练轻量分类头或声源提取模型前，至少完成：

1. 人工复核 7 条核心物种录音及其有效区间；
2. 人工审核 23 条背景候选；
3. 每个核心物种补充至少 3 个独立源录音；
4. 采集不参与训练的杭州手机现场测试录音；
5. 按人工标签重新生成无同源泄漏的数据划分。

验证命令：

```powershell
uv run python scripts/validate_stage2.py
```

验证结果写入 `data/metadata/stage2_validation.json`。
